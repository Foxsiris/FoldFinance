# FoldFinance — личный финансовый трекер для Galaxy Z Fold 8

Этот файл — постоянный контекст проекта. Читай его в начале каждой сессии. Задачи по этапам приходят отдельными промптами (см. `STAGES.md`).

## Что строим

Нативное Android-приложение для **личного** учёта финансов. Устанавливается как APK (sideload), в Google Play не публикуется.

Приложение само собирает операции из банковских SMS (история + новые) и банковских push-уведомлений (только новые), парсит их, хранит локально и строит аналитику. К банкам не подключается, логины и пароли не запрашивает.

## Целевое устройство

Samsung Galaxy Z Fold 8 (стандартный, «широкий»), Android 16+:

- **Внешний экран:** 5.5", 16:10, ширина Compact.
- **Внутренний экран:** 7.6", 4:3. Естественная ориентация в разложенном виде — альбомная, шарнир вертикальный по центру. Ширина Expanded или верхний Medium; точные dp измерить на устройстве (этап 0).

Если устройство окажется Fold 8 Ultra (6.5" / 8.0"), логика та же, меняются только размеры. Раскладка всегда определяется размером окна и позой, а **не** моделью устройства.

## Стек

- Графики: Vico (Compose).
- `androidx.biometric`.
- Glance для виджета.
- `kotlinx.serialization`.
- Тесты:
  - JUnit, Truth, Turbine;
  - Robolectric;
  - Roborazzi (скриншот-тесты).

Версии — актуальные стабильные, через `gradle/libs.versions.toml`. Не выдумывай версии и API. Если не уверен, проверь документацию или спроси меня.

## Модули

- `:parser` — **чистый Kotlin/JVM**, без Android-зависимостей. Распознавание сообщений. Тесты гоняются без эмулятора.
- `:core` — модели домена, Room, репозитории, use-cases, аналитика.
- `:app` — UI, DI, ingest (SMS, уведомления), security, settings, widget.

Больше модулей не заводить без явной причины. Внутри модулей делить по пакетам. UI не содержит бизнес-логики, она живёт в ViewModel и use-cases.

## Инварианты домена (не нарушать)

- **Деньги:** `Long` в минорных единицах (копейки) + ISO-код валюты. Никаких `Double`/`Float` для сумм.
- **`Transaction`:**
  - `id`, `occurredAt`, `amountMinor`, `currency`;
  - `direction`: `EXPENSE` | `INCOME` | `REFUND` | `INTERNAL_TRANSFER`;
  - `kind`: `PURCHASE` | `TRANSFER` | `CASH_WITHDRAWAL` | `TOP_UP` | `CREDIT` | `REFUND` | `FEE` | `SUBSCRIPTION` | `FX` | `UNKNOWN`;
  - `merchant`, `cardMask`, `categoryId`;
  - `confidence`, `needsReview`;
  - `source`: `SMS` | `PUSH` | `MANUAL`;
  - `dedupKey`, `createdAt`, `updatedAt`.
- **`RawMessage`:**
  - поля: отправитель/пакет, `receivedAt`, текст (БД зашифрована), `parseStatus`, `parserVersion`, ссылка на транзакцию;
  - нужна для перепарсинга после улучшения парсера;
  - уведомления **не из белого списка** не сохраняются вообще.
- **Дедупликация:**
  - точная — по идентичности источника (SMS `_id`; для уведомлений `key` + `postTime` + хеш текста);
  - кросс-источниковая — та же сумма, валюта и маска карты в окне ±3 мин из SMS и PUSH → одна транзакция, оба `RawMessage` привязаны к ней;
  - повторное сканирование идемпотентно.
- **Возврат** (`REFUND`) уменьшает расходы своей категории и **не является доходом**. По возможности связывается с исходной покупкой.
- **Переводы между своими картами** (пользователь помечает свои маски карт) — `INTERNAL_TRANSFER`, исключаются из доходов и расходов.
- **Остаток:**
  - если в сообщении есть «Баланс/Остаток» — хранить как известный остаток по карте с временем: «Остаток *1234 на 14:05»;
  - сумма по операциям подписывается «по известным операциям» и никогда не выдаётся за банковский баланс.
- **Неуверенность:** если тип или сумма не уверены — `needsReview = true`. Никогда не угадывать молча.
- **Только реальные данные:** вся статистика считается из БД. Демо-данные и фикстуры — только в тестах и debug-меню, в release их нет.

## Парсер

- Интерфейс `BankParser`: `canHandle(source)` + `parse(text, meta): ParseResult` (`Parsed` | `NotFinancial` | `Uncertain`).
- `ParserRegistry`:
  - выбор по адресу SMS (`900`, `Tinkoff`, `Alfa-Bank`, …) или имени пакета уведомления;
  - fallback — `GenericParser` с низким `confidence`.
- **Форматы сумм:**
  - разделители: `1 500,00 ₽`, `1500.00 RUB`, `1 500р`, `1,500.00`;
  - знаки валют: `$12.50`, `12,50 USD`, `€`;
  - пробелы: NBSP и тонкий пробел;
  - знаки `+`/`−`.
- **Фикстуры:** `parser/src/test/resources/fixtures/<bank>/NNN.txt` + `NNN.expected.json`.
  - Новый формат = сначала фикстура, потом код (TDD).
  - В фикстурах только обезличенные данные.
- **Версия:** константа `PARSER_VERSION`. При изменении — фоновый перепарсинг `RawMessage` со старой версией. Ручные правки пользователя не перезаписывать.

## Два экрана Fold 8 — главное требование к UI

Принцип: **внешний экран — быстрый режим одной рукой, внутренний — рабочий режим с несколькими панелями**. Переключение мгновенное и без потери состояния.

Раскладка выбирается по `WindowSizeClass` + `FoldingFeature`. Тогда всё работает и в split-screen, и в pop-up окне Samsung.

### Внешний экран (Compact)

- `NavigationBar` снизу. Ключевые действия — в нижней половине (зона большого пальца), крупные тач-цели.
- **Главная:** карточка «Сегодня / Месяц», лента последних операций, FAB «Добавить» с цифровой клавиатурой.
- **Очередь проверки:** операции с `needsReview` показываются карточками. Свайп вправо — подтвердить, влево — изменить категорию. Разбирается за секунды одной рукой.
- Остальные экраны — одноколоночные; деталь открывается поверх списка.

### Внутренний экран (Medium / Expanded)

- `NavigationRail` (через `NavigationSuiteScaffold`).
- **Две панели уже с Medium:** `calculatePaneScaffoldDirectiveWithTwoPanesOnMediumWidth`.
- **Обзор:**
  - слева — сводка, график, разбивка по категориям;
  - справа — список операций;
  - тап по категории или дню на графике фильтрует список рядом, без навигации.
- **История:** `ListDetailPaneScaffold` — список слева, деталь/редактор справа. Фильтры — постоянная панель над списком.
- **Аналитика:** `SupportingPaneScaffold` — широкий график в основной панели, выбор периода и разбивка в поддерживающей. Тап по точке графика → операции этого дня в поддерживающей панели.
- **Проверка:** список `needsReview` слева, редактор справа, массовое назначение категории.
- **Подписки:** список слева, календарь ближайших списаний справа.
- **Drag & drop** операции на чип категории (только внутренний экран, этап полировки).

### Шарнир и позы

- Следить за `FoldingFeature` через `WindowInfoTracker`. Когда шарнир разделяет окно (`isSeparating` или `HALF_OPENED`), граница панелей проходит **ровно по шарниру**. Ни текста, ни интерактивных элементов поперёк шарнира.
- **Книжная поза** (вертикальный шарнир, естественная ориентация внутреннего экрана): левая/правая панели.
- **Flex/tabletop** (горизонтальный шарнир, `HALF_OPENED`):
  - верхняя половина — график и сводка (смотреть);
  - нижняя — период, фильтры, список (трогать).

### Непрерывность при складывании (критично)

- При сложении и раскладывании сохраняются:
  - выбранная операция, позиции скролла, фильтры, период;
  - открытый редактор и несохранённый ввод.
- Состояние живёт в ViewModel + `SavedStateHandle`. Выбор хранится в навигаторе панелей, а не в локальном `remember`.
- **Сценарий 1:** открыл операцию на внешнем экране → разложил → видишь список и эту операцию справа.
- **Сценарий 2:** сложил с открытой деталью → на внешнем экране деталь, «Назад» ведёт к списку.
- **Ориентация и окно:**
  - ориентацию не блокировать, `resizeableActivity="true"`;
  - всё переживает пересоздание Activity — проверять с «Не сохранять действия».
- Edge-to-edge, `WindowInsets`: вырез камеры, панель задач Samsung на внутреннем экране, клавиатура.

### Виджет

Glance-виджет для рабочего стола внешнего экрана:

- расходы сегодня и за месяц;
- счётчик «на проверку»;
- кнопка быстрого добавления.

### Проверка раскладок

- **Preview** для трёх конфигураций: внешний экран, внутренний развёрнутый, tabletop.
- **Roborazzi**-скриншоты каждого основного экрана в этих трёх конфигурациях, в светлой и тёмной теме.
- **Debug-экран «Диагностика окна»:** реальные `widthDp`/`heightDp`, size class, список `FoldingFeature` (bounds, state, orientation). Числа с устройства записать сюда:

  - внутренний: `TODO измерить`.

## Android: разрешения и ограничения

- **Разрешения:** `READ_SMS`, `RECEIVE_SMS`; `NotificationListenerService` (`BIND_NOTIFICATION_LISTENER_SERVICE`); `POST_NOTIFICATIONS`; `USE_BIOMETRIC`.
- **Объяснение перед запросом:** каждое разрешение запрашивается с экраном «зачем это нужно».
- **Ограниченные настройки:** для sideload APK Android блокирует доступ к SMS и уведомлениям. Онбординг ведёт пользователя: «Сведения о приложении → ⋮ → Разрешить ограниченные настройки», затем повторная проверка.
- **Батарея Samsung:**
  - экран-инструкция «Батарея → Приложения без спящего режима»;
  - в настройках — статус здоровья слушателя (`onListenerConnected`/`onListenerDisconnected`) и кнопка `requestRebind`.
- **Надёжность SMS:**
  - помимо `BroadcastReceiver` — периодический `WorkManager`-job «дельта-скан» SMS после `lastProcessedSmsId`;
  - ни одна SMS не теряется, даже если ресивер не сработал.
- **Белый список уведомлений:** парсятся только пакеты из белого списка. Остальные уведомления отбрасываются сразу в `onNotificationPosted`, ничего не сохраняется.
- Обходить системные ограничения нельзя. Если что-то невозможно — сказать и предложить корректную альтернативу.

## Безопасность и приватность

- **В манифесте нет `INTERNET`.** Проверять merged manifest; если библиотека добавляет — `tools:node="remove"`. Никаких аналитик, crash-SDK, облачных API.
- **БД:** SQLCipher, ключ генерируется и оборачивается Keystore.
- **Системный бэкап выключен:** `allowBackup="false"` + `dataExtractionRules`, исключающие всё.
- **Блокировка:**
  - `BiometricPrompt` с fallback на `DEVICE_CREDENTIAL`;
  - повторная блокировка после N минут в фоне;
  - `FLAG_SECURE` (переключатель в настройках, по умолчанию вкл).
- **Экспорт / импорт:**
  - зашифрованный файл: AES-GCM, ключ из пароля пользователя через PBKDF2/Argon2;
  - выбор места через SAF (`CreateDocument`/`OpenDocument`);
  - валидация при импорте.
- **Логи:** в release не логировать тексты сообщений и суммы. Timber только в debug, с редактированием.

## Правила работы

- Каждый этап начинать с плана: какие файлы, какие решения, какие тесты. Потом реализация.
- После изменений — сборка + релевантные тесты. Отчёт в конце этапа: что сделано, что проверено, что осталось.
- Никаких кнопок-заглушек и `TODO()` в release-UI. Не готово — скрыть.
- Форматы банков не выдумывать. Если нет образца — спросить меня или пометить `Uncertain`.
- Строки UI на русском в `strings.xml`, код и идентификаторы на английском. KDoc для публичного API доменного слоя и парсера.
- Room-схемы экспортировать, миграции писать явно и тестировать (`MigrationTestHelper`).
- Коммит после каждого этапа, conventional commits.
