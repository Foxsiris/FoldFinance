# Промпты по этапам для Claude Code

## Как работать

1. Положи `CLAUDE.md` в корень пустой папки проекта и запусти там `claude`.
2. **Один этап — одна сессия.** Между этапами — `/clear`, контекст держит `CLAUDE.md`.
3. Каждый этап начинай в plan mode (Shift+Tab дважды), прочитай план, потом разреши реализацию.
4. Перед этапом 1 положи обезличенные SMS и тексты пушей своих банков в `parser/src/test/resources/fixtures/raw/<bank>/`.
   - Чем больше форматов (покупка, перевод, возврат, комиссия, валюта, зачисление), тем лучше парсер.
   - Тексты пушей можно скопировать из шторки или истории уведомлений Samsung.
5. Телефон подключён по USB (или Wireless debugging), чтобы Claude мог делать `installDebug` и `adb logcat`.

---

## Этап 0 — каркас и диагностика экранов

```
Прочитай CLAUDE.md. Создай Android-проект по описанному стеку.

Что нужно:
- модули :app, :core, :parser;
- version catalog, Hilt, Compose + Material 3 + material3-adaptive, WindowManager;
- в манифесте нет INTERNET (проверь merged manifest), allowBackup=false;
- NavigationSuiteScaffold с пустыми разделами: Обзор, История, Аналитика, Проверка, Настройки.
  Пустые разделы видны только в debug.
- Debug-экран «Диагностика окна»: widthDp/heightDp, WindowSizeClass, позиция и состояние
  каждого FoldingFeature. Обновляется в реальном времени при складывании.
- Настрой Roborazzi и Preview-конфигурации для внешнего экрана, внутреннего и tabletop.

Готово, когда:
- assembleDebug и тесты зелёные;
- приложение установлено на телефон;
- я снял показания диагностики на обоих экранах, и ты вписал их в CLAUDE.md.
```

## Этап 1 — парсер (TDD)

```
Прочитай CLAUDE.md, раздел «Парсер».

В fixtures/raw/ лежат мои обезличенные сообщения:
- для каждого составь .expected.json и покажи мне таблицу на проверку до написания кода;
- после моего ОК реализуй в :parser модели ParseResult, AmountParser (все форматы из CLAUDE.md),
  ParserRegistry, парсеры для каждого банка из фикстур и GenericParser.

Обязательные кейсы:
- возврат ≠ доход;
- комиссия — отдельная операция;
- валютная покупка;
- перевод себе;
- рекламная SMS банка → NotFinancial;
- код подтверждения → NotFinancial;
- нераспознанное → Uncertain.

Готово, когда :parser:test зелёный и каждая фикстура покрыта тестом.
```

## Этап 2 — данные

```
Прочитай CLAUDE.md, разделы «Инварианты домена» и «Безопасность».

В :core реализуй:
- Room + SQLCipher с ключом через Keystore;
- сущности Transaction, RawMessage, Category, MerchantRule, Card (с флагом «моя карта»),
  KnownBalance, Subscription;
- DAO на Flow, репозитории;
- дедупликацию (точную и кросс-источниковую);
- use-case перепарсинга по PARSER_VERSION с сохранением ручных правок;
- экспорт схем.

Тесты:
- дедуп SMS + PUSH одной операции;
- повторный импорт не плодит дубли;
- REFUND уменьшает расходы категории;
- INTERNAL_TRANSFER не попадает в итоги.
```

## Этап 3 — SMS: импорт истории и новые сообщения

```
Реализуй ingest SMS в :app.

Онбординг:
- экран «зачем нужен доступ к SMS»;
- запрос READ_SMS / RECEIVE_SMS;
- инструкция про «Разрешить ограниченные настройки» для sideload с повторной проверкой.

Первичное сканирование:
- WorkManager с прогрессом, экран показывает «просканировано / найдено / доходы / расходы»;
- можно свернуть приложение — сканирование продолжится.

Дальше:
- повторное сканирование из настроек (идемпотентное);
- BroadcastReceiver новых SMS;
- периодический дельта-скан после lastProcessedSmsId.

Проверь на эмуляторе через `adb emu sms send` и на моём телефоне.
```

## Этап 4 — push-уведомления

```
Реализуй NotificationListenerService.

Онбординг доступа к уведомлениям (с ограниченными настройками).

Экран выбора источников:
- список установленных приложений с иконками, банки сверху (по известным пакетам);
- белый список хранится в DataStore.

Обработка:
- уведомления не из белого списка отбрасываются сразу;
- из белого списка → RawMessage → парсер → дедуп с SMS.

Здоровье слушателя:
- статус connected/disconnected в настройках;
- кнопка requestRebind;
- экран-инструкция про «Приложения без спящего режима» Samsung.

Debug-меню: «отправить тестовое банковское уведомление», свой пакет в белом списке только в debug.
```

```
Прочитай CLAUDE.md, раздел «Два экрана Fold 8» — это главная часть этапа.

Реализуй Обзор, Историю, деталь/редактирование операции, ручное добавление и очередь Проверки:

- внутренний — панели (ListDetailPaneScaffold, две панели уже с Medium), граница по шарниру;
- история: сортировка, фильтры (категория, сумма, тип, период), поиск, удаление;

Готово, когда:
- оба сценария непрерывности из CLAUDE.md работают на телефоне;
- работает «Не сохранять действия»;
- есть Roborazzi-скриншоты каждого экрана в трёх конфигурациях × светлая/тёмная тема.
```

## Этап 6 — категории и обучение

```
Категории:
- базовые: Продукты, Транспорт, Развлечения, Покупки, Рестораны, Коммуналка, Подписки,
  Здоровье, Переводы, Другое;
- пользователь может добавлять, переименовывать и выбирать иконку/цвет.

Автокатегоризация:
- встроенный словарь мерчантов (ключевые слова по-русски и латиницей);
- MerchantRule из исправлений пользователя: после исправления спросить
  «Применять для всех операций от X?», при согласии применить и к прошлым.

На внутреннем экране — drag & drop операции на чип категории.

Тесты на приоритет: правило пользователя > словарь > Другое.
```

## Этап 7 — аналитика

```
Аналитика на Vico:
- периоды: день, неделя, месяц, год, произвольный;
- расходы и доходы, топ категорий, среднее в день, динамика;
- сравнение с прошлым периодом, соотношение доходов и расходов.

Раскладки:
- внутренний экран: SupportingPaneScaffold, тап по точке → операции дня рядом;
- tabletop: график сверху, управление снизу;
- внешний: компактные карточки + один график.

Мультивалюта: итоги по каждой валюте отдельно, без сетевых курсов.

Unit-тесты на все расчёты, включая границы периодов и часовой пояс.
```

## Этап 8 — подписки

```
Детектор регулярных платежей:
- признак: тот же мерчант, сумма ±10%, интервал ~7 / ~30 / ~365 дней, минимум 3 повтора
  (для годовых — 2);
- кандидат → карточка «Похоже на подписку, подтвердить?».

Экран подписок:
- сумма в месяц, дата следующего списания;
- на внутреннем экране — календарь списаний справа.

Тесты на детектор с синтетической историей.
```

## Этап 9 — безопасность и настройки

```
Блокировка:
- BiometricPrompt + DEVICE_CREDENTIAL, повторная блокировка по таймауту;
- FLAG_SECURE с переключателем.

Зашифрованный экспорт/импорт через SAF по CLAUDE.md, тест «экспорт → чистая установка → импорт».

Экран настроек полностью:
- разрешения со статусами;
- источники уведомлений, повторное сканирование;
- мои карты (для внутренних переводов), валюта по умолчанию, категории;
- бэкап, тема (системная/светлая/тёмная), включение/выключение автоотслеживания.
```
